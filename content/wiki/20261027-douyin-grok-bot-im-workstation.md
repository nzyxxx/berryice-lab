## 这条讲什么

作者把 Grok Bot 当成设备与 IM 之间的**中间件 / 中转调度层**：一是打通微信等 IM，让 Bot/设备成果推到手机；二是给 24h 本地工作站配专属管家 Bot（心跳 + 远程调用）。末尾用「手机下指令 → Mac mini 跑长任务 → 成品回微信」串起来演示。

## 核心要点

1. **两招玩法**
   - **打通 IM**（微信/钉钉/飞书）：发送入口（随手派活）+ **接收入口**（其他 Bot/设备成果回手机）；作者更看重后者。
   - **打通本地工作站**：闲置机能常驻；配专属管家 Bot，写入静态 IP / 机器码，定时心跳，异常经微信通知。
2. **微信怎么连（演示路径）**
   - 参考 King 老师长文 + 朋友「铁柱」整理的全流程 Prompt；自称走腾讯官方文档连接方式。
   - 让 Bot 建 **webhook 触发的 routine** → 粘贴 webhook 链接与密钥 → 扫短时效验证码 → 微信收首条连接消息后即可派活。
   - 默认可先只有纯文本转发；再让 Bot 补上图片/文件能力，即可推图与附件。
3. **为何要本地 AI 工作站**
   - agent 不能停、部分活不适合全丢云电脑；本地绑定 Claude Code / NAS 等；需要随时远程调用。
   - 与「工具型 Bot（只调本机某工具）」不同：管家 Bot 是**整机连接器**。
4. **长任务演示形态**
   - 手机语音下指令 → 挂到 Mac mini 上的 Bot → 本机命令行/Claude Code 侧生成约 15s 手绘风短片 → MP4 经微信推回；固定流程可改成定时任务，人只收结果。
5. **定位一句话**：云端挂轻任务与定时、工作站扛重度本地生产、IM 做输入与验收、手机做补充入口——Grok Bot = 资源中转调度，而不只是个人助理。
